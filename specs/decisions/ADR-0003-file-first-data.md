# ADR-0003 — رویکرد File-first برای داده تحلیلی نسخه نخست

- وضعیت: پیشنهاد برای بازبینی؛ انتخاب زیرساخت نهایی باز است
- تاریخ: 2026-11-20
- تصمیم مرتبط: PX-DATA-001

## زمینه

PredictX در مرحله MVP پژوهشی است. بار اصلی مورد انتظار، ورود و تحلیل batch داده تاریخی کندلی و اجرای آزمایش‌های قابل بازتولید است. هنوز منبع داده، حجم، نرخ ingest، نیاز هم‌زمانی و محیط استقرار مشخص نیست.

## تصمیم پیشنهادی

رویکرد **File-first و dataset-versioned** مبنای طراحی قرار گیرد:
- snapshot خام منبع بدون تغییر و همراه checksum نگهداری شود.
- داده canonical تحلیلی در یک قالب ستونی نسخه‌پذیر مانند Parquet ارزیابی شود.
- manifest و QualityReport برای هر DatasetVersion ثبت شوند.
- Git فقط کد، مستندات، schema و تنظیمات غیرمحرمانه را نگه دارد؛ نه داده بازار و artifact حجیم.
- انتخاب catalog metadata (manifestهای فایل‌محور، SQLite یا پایگاه داده server-based) تا benchmark و تعیین نیاز هم‌زمانی باز بماند.

## گزینه‌ها

1. **File-first + Parquet:** گزینه پیشنهادی برای تحلیل batch و اسکن تاریخی؛ ساده و قابل انتقال، اما مدیریت metadata و هم‌زمانی نیازمند طراحی است.
2. **CSV-only:** ساده و قابل مشاهده، اما برای schema، نوع decimal، حجم و evolution محدودتر است؛ تنها قالب تبادل/نمونه‌گیری باشد.
3. **Database-first:** برای query هم‌زمان و دسترسی چندکاربره می‌تواند مناسب باشد، اما پیش از شناخت الگوی بار و استقرار، هزینه و پیچیدگی غیرضروری ایجاد می‌کند.
4. **ترکیبی:** در صورت نیاز، فایل‌های ستونی برای داده حجیم و پایگاه داده برای catalog/metadata؛ تصمیم بعدی بر اساس benchmark.

## پیامدها

مزایا:
- datasetها به‌صورت snapshot مستقل قابل hash و بازتولیدند.
- داده خام از canonical جدا می‌ماند.
- اجرای آزمایش تاریخی به زیرساخت پایگاه داده پیچیده وابسته نیست.

ریسک‌ها:
- مدیریت concurrency و تراکنش‌ها در catalog فایل‌محور محدودتر است.
- partitioning نامناسب می‌تواند عملکرد را کاهش دهد.
- اصلاح داده و backfill نیازمند ساخت نسخه جدید و محاسبه delta است.

## شرایط بازنگری

پس از انتخاب provider و دریافت نمونه مجاز، benchmark روی حجم واقعی/نماینده اجرا شود. اگر نیاز به query هم‌زمان، به‌روزرسانی مکرر، چندکاربره یا تراکنش‌های metadata وجود داشت، گزینه پایگاه داده یا معماری ترکیبی با ADR جدید بررسی شود.

این ADR انتخاب قطعی Parquet، SQLite، PostgreSQL یا cloud storage نیست.
