## دروازه‌های کیفیت
- هر نتیجه باید dataset/version و experiment protocol داشته باشد.
- هیچ تغییر schema بدون migration و تست سازگاری انجام نمی‌شود.
- داده خام و credential در Git commit نمی‌شوند.
- معیارهای پذیرش و تست‌های ضد look-ahead پیش از انتشار اجرا می‌شوند.
- detector نباید به outcome یا داده آینده وابسته باشد.
- هر pipeline باید با fixture و تست‌های قرارداد قابل ارزیابی باشد.
- هر DatasetVersion منتشرشده immutable است و اصلاح داده نسخه جدید می‌سازد.
- زمان نامعلوم به UTC حدس زده نمی‌شود؛ duplicate متعارض و کیفیت نامعلوم پنهان نمی‌شوند.

## تصمیم فناوری
زبان، ذخیره‌سازی، پایگاه داده، orchestration و UI تا روشن‌شدن منبع داده و نیازهای عملیاتی باز می‌مانند. معماری MVP بر Modular Monolith و pipelineهای مرحله‌ای استوار است؛ رویکرد File-first برای داده تحلیلی پیشنهاد شده و باید با نمونه واقعی benchmark شود.
